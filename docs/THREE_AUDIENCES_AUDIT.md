# Three-audience audit

**Brief:** `docs/three-audiences-governance-brief.md` · **Audit date:** 23 November 2026 · **Research cutoff (unchanged):** 22 November 2026
**Baseline measured on:** commit `910adc1` (the live site before this work), built locally with the same generator.

The brief asks that every decision serve three audiences at once: the human reader, the maintainer and the AI agent, from one factual record. This audit records where the site stood before the change, measured rather than assumed, and what each new file is for.

## 1. What already worked (kept unchanged)

| Strength | Evidence in the repository |
|---|---|
| One canonical record | Every page is generated by `site/build.py` from `research/` (CSV and Markdown). The templates hold layout and labels only. |
| Stable IDs | Claim IDs C001 to C222 and source IDs S001 to S180, append-only. No ID was renumbered in this work. |
| Four evidence labels, two separate ratings | `evidence-map.csv`, `interventions.csv`: problem exists versus intervention works. Validator rejects any other label. |
| Verification practice | `research/VERIFICATION.md`, `verification.csv` (figure-level re-check), `source-checks.csv` (reachability, 177 of 180). |
| A propagation test | `site/qa/rating_change_test.py`: changing a rating in the CSV changes the page. |
| Browser QA | `site/qa/qa.js`: axe (WCAG 2.1 and 2.2 AA), links and anchors, reflow at 320 px, print, logos, weight, journeys. 26 of 26 passing at baseline. |
| Corrections and update policy pages | `about/corrections.html`, `about/update-policy.html` existed as prose. Phase 2 corrections lived only in a table inside the verification record. |
| CI | `.github/workflows/pages.yml`: validate, build, deploy on `main`. |

## 5. Conflicts with existing standards (resolved in favour of the existing standard)

| Brief rule | Existing standard | Decision |
|---|---|---|
| No em dashes anywhere | `CLAUDE.md` fixes the home link's accessible name as "Clean Air — home" | Kept. It is an accessible name mandated by the project rules, outside page prose. Listed for the owner (decision 6). |
| Four base containers `.ca-card/.ca-note/.ca-row/.ca-panel` "only if those do not already exist" | Existing families (`.card`, `.org-card`, `.notice`, `.layer.simple`, `.flow`, `.explorer` ...) | Not renamed. Registered into four families in `tools/design-tokens.json`; the card check rejects unregistered containers. |
| Claim status vocabulary (established, reported, inferred, disputed, withdrawn) | Existing `read` / `provisional` | Kept and extended with `withdrawn`. Provenance class and verification state carry the "reported / inferred" distinction instead of overloading status. |
| Outcome category per claim | No reliable field to derive it from | Not invented. Outcome levels are kept where records already separate them: activities, outputs, measured outcomes and independent evaluation on profiles and activity records. |

## 6. Decisions that need the owner

1. Licence for the site's original writing, data and graphics (currently "not yet decided" on the reuse page and in the catalogue).
2. Whether AI model training on the site's writing is permitted.
3. A real maintainer contact and expiry date before any `security.txt` is published.
4. `robots.txt` and `llms.txt` only take effect at a domain root; on `arunbh2.github.io/clean-air/` crawlers do not look there. A custom domain would fix this.
5. Terms of use, if wanted.
6. Whether to change the mandated accessible name "Clean Air — home" (em dash) in `CLAUDE.md`.
